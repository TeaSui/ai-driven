# Ground factual claims

Use inspected files/tool output for repository claims and current primary documentation or installed help for version-sensitive APIs, settings and CLI flags. Cite load-bearing file locations or source links. Mark inferences and unknowns; never invent paths, symbols, flags, commits or successful tool results.

Search before reading large files and inspect the relevant region. Run relevant checks before claiming success; report what actually ran and its limits. A static parse does not prove model access or runtime correctness. Recheck earlier evidence only when changes, failures or uncertainty justify it.

Dispatchers verify cited evidence exists, read the decisive results and retain unresolved concerns. Use `skills/grounding-claims` for a detailed evidence workflow and `skills/verification-before-completion` before completion claims. Ask for concise decisions/rationale, not private chain-of-thought. Design challenge and review bounds are in `rules/workflow-routing.md` and `rules/review-loop-limits.md`.
